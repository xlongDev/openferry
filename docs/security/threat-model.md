# 威胁模型

> 状态：v0.1。范围：本机网关 + 桌面应用 + 供应商网络调用。不含：远程多租户部署（暂不支持）。

## 1. 资产

| 资产                               | 影响                       | 存放位置                                              |
| ---------------------------------- | -------------------------- | ----------------------------------------------------- |
| 供应商 API Key                     | 直接经济损失、账号被封     | 操作系统凭据存储（阶段 3）；当前为进程内存 + 环境变量 |
| 网关访问 Token                     | 本机任意进程可白嫖模型额度 | 数据目录 `0600` 文件                                  |
| 客户端配置文件（`models.json` 等） | 破坏用户既有配置           | 用户主目录                                            |
| 用户提示词与模型输出               | 隐私泄露                   | **不落盘**（默认）                                    |
| 请求元数据（模型、耗时、错误）     | 行为画像                   | SQLite（阶段 3）                                      |

## 2. 信任边界

```
[不可信] 浏览器页面 ──Origin──▶ 网关 ──▶ 供应商
[不可信] 本机任意进程 ──Token──▶ 网关
[不可信] 供应商响应 ──JSON/SSE──▶ 网关
[不可信] 用户填的供应商 URL ──DNS──▶ 内网/元数据服务
[可信]   Electron main ◀──IPC──▶ preload ◀──▶ renderer（沙箱）
```

**关键判断：本机不等于可信。** 同机上的任何进程、任何网页都能访问 `127.0.0.1`，因此 loopback 监听不等于安全边界。

## 3. 威胁与缓解

### T1 浏览器跨站调用本地端口

- **场景**：用户访问恶意网页，页面 `fetch('http://127.0.0.1:41980/v1/chat/completions')` 消耗额度或读取数据。
- **缓解**：任何带 `Origin` 头的请求直接 `403`（与 OC Ferry 一致）。不依赖 CORS —— CORS 只阻止读取响应，不阻止请求产生副作用。
- **测试**：`packages/gateway/test/security.test.ts`。

### T2 DNS rebinding

- **场景**：攻击者域名先解析到公网，再解析到 `127.0.0.1`，绕过「只允许公网」的判断。
- **缓解**：`Host` 头白名单（只接受配置的 `host:port`）；供应商 URL 解析后校验 IP 段；不使用 `follow` 式重定向。
- **状态**：Host 校验已实现；供应商 URL 的 IP 校验已实现（`core/net-guard.ts`），DNS 解析后的二次校验在阶段 3 落地（需要实际解析，见 `docs/security/security-policy.md` §4）。

### T3 SSRF：供应商 URL 指向内网

- **场景**：用户（或被诱导的用户）把供应商地址填成 `http://169.254.169.254/latest/meta-data/`。
- **缓解**：`assertSafeProviderUrl()` 拒绝非 `http(s)` 协议、拒绝云元数据地址、拒绝 link-local；loopback/私网必须显式开启 `allowPrivateNetwork`。
- **已知缺口**：当前是**字面量 + 主机名**判断，尚未在连接时固定解析后的 IP（真正的 rebinding 防护需要自定义 `lookup`）。记录在路线图 P1。

### T4 密钥泄露到日志 / 诊断报告

- **场景**：错误对象里带上了 `Authorization` 头，被 `JSON.stringify` 写进日志。
- **缓解**：`redact()` 对 `authorization`、`api_key`、`token`、`cookie`、`set-cookie` 等键名做掩码；日志只接受结构化字段，不接受任意对象展开。
- **测试**：`packages/core/test/redact.test.ts` 覆盖嵌套对象、数组、URL query 中的 `key=`。

### T5 渲染进程被 XSS 后提权

- **缓解**：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；preload 只暴露固定方法名，不暴露 `ipcRenderer` 本身；主进程对每个 IPC 通道做 Zod 校验并校验 `event.senderFrame`。
- **测试**：`apps/desktop/test/ipc.test.ts`（对 handler 做纯函数测试）。

### T6 客户端配置被破坏

- **缓解**：读 → 校验 → 算 diff → 检测外部修改 → 备份 → 临时文件 → 校验 → 原子 rename → 重读校验。任何一步失败都保留备份。
- **状态**：阶段 5 实现。

### T7 资源耗尽

- **缓解**：请求体上限（默认 1 MiB）、并发闸门（默认 16）、上游连接/首事件/总时长超时、SSE 背压（`write()` 返回 false 时暂停读取）。
- **测试**：`packages/gateway/test/limits.test.ts`。

### T8 上游返回畸形数据导致进程崩溃

- **缓解**：所有解析点都 `try/catch` 并转为 `ProtocolError`；流式解析器把非法 JSON 作为事件产出而不是抛出。
- **测试**：SSE 非法 JSON 用例。

## 4. 明确接受的风险

| 风险                                   | 理由                                         | 复核条件                     |
| -------------------------------------- | -------------------------------------------- | ---------------------------- |
| 同机进程可读网关 Token 文件            | 无 OS 级隔离手段（不做内核扩展）             | 若支持远程访问则必须重新评估 |
| 不做代码签名（macOS 首次打开需右键）   | 无 Apple 开发者账号                          | 发布 RC 前                   |
| 不实现动态插件沙箱                     | 首版无插件                                   | 引入第三方插件时             |
| 供应商 URL 的 DNS rebinding 防护不完整 | 需要自定义 socket lookup，工作量大于当前收益 | 开放远程供应商配置时         |

## 5. 复审触发条件

任何一条成立就必须重做本文件：新增远程访问、新增插件机制、新增客户端配置写入路径、新增凭据存储方式、新增多用户支持。
