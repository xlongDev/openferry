## 2. 可验证的功能范围（依据 README 与提交信息）

1. **隔离运行时**：在应用数据目录里放一份 OpenCode，自带 XDG 目录、随机口令、环境变量白名单，不碰用户已安装的 OpenCode。
2. **免费判定**：只看价格字段（输入/输出/缓存读写全为 0），不看模型名；已声明 `deprecated` 的排除。
3. **能力体检**：给模型 5 个工具、自由选择，让它读一个带随机 token 的文件；只回文本判定为「可用·仅对话」并关闭工具；动作不符重试一次；超时与格式失败不重试。
4. **并发与缓存**：3 路并发（一轮约 60 秒）；成功判定缓存 6 小时，负载类 10 分钟，结论类 1 小时。
5. **写入客户端配置**：WorkBuddy 的 `~/.workbuddy/models.json`、DSH 的 `~/.dsh/profiles/*/cordis.patch.yml`；只增删自己标记的条目，写前备份、加锁、原子替换，退出时清理。
6. **本机转发口**：`127.0.0.1:41980`，全部路由要求 `Authorization: Bearer <数据目录>/api-key`，带 `Origin` 头一律 403，并发上限 4。
7. **接口**：`GET /health`、`GET /v1/models`、`POST /v1/chat/completions`（支持 stream），以及一组 `/admin/*` 控制端点。
8. **形态**：Electron 托盘应用 + 后台服务；macOS（Apple Silicon）与 Windows 有安装包；Linux 标注为实验性。

## 3. 它自己承认的限制（README「诚实交代」）

- 启动后自动发检测请求，会消耗少量免费额度。
- 检测通过只代表「这一次能按协议产生动作」，不代表完整工作流可用。
- 界面耗时是完整请求用时，不是首字延迟；剩余额度上游不提供。
- 免费模型与额度由上游决定，随时变化。
- 系统代理只支持手动 HTTP/HTTPS，不支持 PAC/SOCKS。

## 4. 对 OpenFerry 的启示

**要继承的**：

- 「隔离运行时」的思路 → 我们扩展为「供应商凭据与客户端配置都不进入普通日志/诊断」。
- 「判定缓存 + 有效期」→ 能力探测结果必须带 `probedAt` 与 `expiresAt`，不能把一次成功当成永久能力。
- 「只增删自己标记的条目」→ 客户端配置写入必须幂等，且不覆盖用户手写内容。
- 「Origin 头一律 403」→ 本地端口不给浏览器用，这一条直接采纳。
- 「写前备份 + 原子替换」→ 采纳为强制流程（见安全策略 9.4 节对应实现）。

**要改进的**：

| 问题       | OC Ferry 的做法                     | OpenFerry 的做法               |
| ---------- | ----------------------------------- | ------------------------------ |
| 单一上游   | 只托管 OpenCode                     | 供应商适配器，多上游并存       |
| 协议单点   | 只为 WorkBuddy 的工具协议做信封翻译 | Canonical Model + 多协议适配器 |
| 状态存储   | JSON 文件 + 缓存文件                | SQLite 版本化迁移（阶段 3）    |
| 客户端绑定 | 硬编码 WorkBuddy / DSH 路径         | 客户端适配器接口 + 路径探测    |
| 诊断       | 无脱敏导出                          | 结构化日志 + 脱敏诊断报告      |
| 认证       | 单一静态 api-key                    | 数据面/管理面分权（阶段 4）    |

## 5. 明确不做的事

- 不复制其源码、不 fork。
- 不绕过任何供应商的认证、额度或使用限制。
- 不宣称「比 OC Ferry 快 N 倍」——没有同机同场景的基准数据之前，这类声明一律不写。
