# ADR 0002 — 网关使用 `node:http`，不引入 Web 框架

- 状态：已接受
- 日期：2026-11-02

## 背景

候选：Fastify / Express / Hono / `node:http`。

网关只有 4 个端点，但有两个非标准需求：**精确控制 SSE 写入与背压**、**在读取 body 之前完成认证与体积限制**。

## 决策

使用 Node 标准库 `node:http`，自己写一个约 60 行的路由表。

## 理由

1. 端点数量少，路由需求是「method + path 精确匹配」，框架的路由树是净负担。
2. SSE 需要 `res.write()` 返回值驱动的背压控制；框架的 `reply.raw` 抽象只会让这件事更绕。
3. 认证必须在读 body 前完成，且要能 `socket.destroy()`；中间件模型会鼓励「先解析再判断」。
4. 依赖越少，供应链攻击面越小 —— 这是本项目的核心卖点之一。

## 后果

- 需要自己实现：404/405、`Content-Type` 解析、body 读取与上限、错误响应格式。这些都已实现并有测试。
- 放弃：自动 OpenAPI 生成、请求装饰器。当前不需要。
- 如果将来端点超过 15 个或需要插件生态，重新评估 Hono（它同样基于 Web 标准，迁移成本低）。
