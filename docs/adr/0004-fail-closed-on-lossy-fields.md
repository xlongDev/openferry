# ADR 0004 — 无法无损转换时「失败」而不是「猜」

- 状态：已接受
- 日期：2026-11-02

## 背景

OpenAI Chat Completions 有大量可选字段（`logprobs`、`n`、`audio`、`modalities`、`parallel_tool_calls`…）。Canonical 不打算 1:1 覆盖全部。

## 决策

三类字段，三种处理：

| 类别                     | 处理                | 例子                                                                                   |
| ------------------------ | ------------------- | -------------------------------------------------------------------------------------- |
| 可无损表达               | 映射                | `temperature`、`tools`、`response_format`                                              |
| 可安全降级且用户可感知   | 降级 + `warnings[]` | `parallel_tool_calls: true` → 上游不支持时串行，并在响应头 `x-openferry-warnings` 说明 |
| 无法表达且降级会改变语义 | **拒绝，400**       | `n > 1`、`logprobs`、`audio`                                                           |

## 理由

静默丢弃字段是本类网关最危险的失败模式：客户端以为功能生效，实际拿到的是另一种语义的结果，而且没有任何信号。

`n: 3` 静默返回 1 条，会让调用方把 `choices[0]` 当成唯一答案；`logprobs` 静默丢弃会让做置信度过滤的应用拿到 `undefined` 却不报错。

## 后果

- 部分客户端可能因为发了 `logprobs` 而直接失败。这是**有意的**：失败可见，静默错误不可见。
- 错误信息必须点名具体字段，便于用户关闭该选项后重试。
- 新增字段时，必须在本 ADR 的表格里归类，否则默认按「拒绝」处理。
